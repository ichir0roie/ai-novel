# worlds

世界観ごとの設定と、その宇宙の本文。**1 ディレクトリ = 1 宇宙**。
1 つの宇宙を複数の作品で共有する。**作品は必ずひとつの宇宙の中で完結する。**

```
worlds/<宇宙名>/
  world.md          宇宙全体の設定（暦・共通現象・星どうしの関係）
  rolls.md          乱数ログ。引いた目とシード、調整の理由
  glossary.md       固有名詞の一覧。表記ゆれ防止
  glossary.md       用語の索引。**自動生成。手で書かない**
  records/          台帳（表）。出来事・行動・指標・関係・火種・場所
  terms/<語>.md      用語。1 語 1 ファイル
  concepts/<名>.md   概念。1 つ 1 ファイル
  stories/<作品名>/   本文。meta.md / plot.md / episodes/
  world.db          台帳を組み上げた SQLite。git には入れない
  <星名>/
    planet.md       天文・地理・空気感
    history.md      年表と、歴史をめぐる争点
    society.md      種族・国家・制度
    characters/     登場人物・組織・国。**1 つ 1 ファイル**
    objects/        道具・現象・施設。**1 つ 1 ファイル**
```

## 二つの形を併存させる

**レコードとして管理しやすい形と、文章として書きやすい形を、両方持つ。**

| | 形 | 何を入れるか |
| --- | --- | --- |
| 表 | `records/*.md` の表。一行 = 一レコード | 行が短くて数が多いもの |
| 記事 | **1 ファイル = 1 レコード。** front matter ＋ 本文 | 文章のつくもの。人物・物・用語・概念 |

記事は front matter がレコード、その下が文章。**同じファイルにあるので二重管理にならない。**
どの台帳に入るかは front matter の `記録:`（人物／物／用語／概念）で決まり、
**置き場所は問わない**。雛形は `python3 tools/chronicle.py template --kind 人物`。

新しい宇宙は `python3 tools/chronicle.py init --world <宇宙名>` で起こす。
台帳の雛形と `stories/` が作られる。

## 原則

- **物語に必要な分だけ作る。** 使われない設定は書かないほうがいい
- **制限を書く。** 能力には必ず代償か制限を設ける。制限のない設定は物語を殺す
- **同じ宇宙の中では矛盾を許さない。** 暦・物理法則・共通現象は星をまたいで一致させる
- **宇宙どうしの矛盾は平行宇宙として許容する。** 別の `worlds/<宇宙名>/` は直さない
- **作品は宇宙をまたがない。** またぎたくなったら、それは別の作品である
- **本文で生まれた設定は必ずここへ書き戻す**
- **固有名詞は 1 つ 1 ファイルで登録する。** `glossary.md` は索引で、`chronicle.py index` が作る
- **名づけは日本語として自然に。** 音読み二字熟語の造語を重ねない（`core/naming.md`）
- **アバウトな要素は乱数で決める。** `tools/roll.py`。引いた目は `rolls.md` に全部残す
- **文章が正、台帳が従。** `records/` は文章から起こす。**台帳にしか存在しない設定を作らない**
- **時間のあるものは台帳にも入れる。** 出来事・行動・数・関係・火種。`tools/chronicle.py`
