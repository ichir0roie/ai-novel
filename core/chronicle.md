# 世界の記録と、話が尽きない仕組み

workflow.md が「**どの順で進めるか**」なら、ここは「**どう貯めるか**」。

## 何のためにあるか

話が続かなくなる理由は、たいてい二つしかない。

1. **前に何を決めたか忘れる。** 設定ファイルを全部読み直さないと書けなくなる
2. **次に何が起きるか思いつかなくなる。** 世界が静止していて、
   書き手が毎回ゼロから事件を発明している

どちらも、**世界の状態を時間つきで持っていない**ことから来る。
だから、設定を文章で持つのとは別に、**記録**として持つ。

## 一レコード一ファイル

**マークダウンの構成は一つに揃える。上部にレコードのカラムごとの値、下部に文章。**
上段がレコード、その下が文章。同じファイルにあるので二重管理にならない。

```markdown
---
種別: 技術
世界: SFファンタジー
星: ノウル
場所:
---

器の大きい者ほど、多く引ける。
（ここから下は人間が読む文章。長さに制限はない）
```

これは `novels/terms/器/器.md`、つまり**語**のレコードである。
`世界` `星` `場所` が並んでいるのは語だからで、**欄はレコードの種類ごとに違う**。
どの欄が使えるかは、このファイルのいちばん下の表を見る。
**決まっていない欄は、空のまま置いてよい**（`場所:` のように）。
語の `場所` は特に、**空のままで構わない。**
どこまで届いている語かは、話が進むにつれて狭まったり広がったりする。
決まった時点で書き足す。

**同じことを二度書かない。** 上段に書いたことを本文で繰り返さない。

**`名` は書かない。** ファイル名・ディレクトリ名がそのまま名になる。
**見出し（`#`）も本文には要らない。** ファイル名が名を持っているので、
中で同じ名を繰り返す一行目は無駄になる。**表と強調（`**...**`）も使わない。**
本文は、地の文と同じ**ただの文章**で書く。表にしたくなったら、
行ごとの関係を一文に言い換えられないか先に考える。

## 置き場所がレコードの種類を決める

**どこに置くかで、何のレコードかが決まる。** 上段には中身だけを書く。

```
novels/
  worlds/<世界線>/<世界線>.md                       場所（いちばん外。種別は「世界線」）
  worlds/<世界線>/**/<場所>/<場所>.md               場所
  worlds/<世界線>/**/<場所>/events/{時刻}_{名}.md   出来事
  objects/<世界線>/<種別>.md                        種別
  objects/<世界線>/**/<個体>/<個体>.md              個体
  objects/<世界線>/**/<個体>/places/{時刻}_{場所}.md  居場所
  objects/<世界線>/**/<個体>/actions/{時刻}_{名}.md   行動
  characters/<出身地>/**/<人名>/<人名>.md           人物
  characters/<出身地>/**/<人名>/places/{時刻}_{場所}.md  人物居場所
  characters/<出身地>/**/<人名>/actions/{時刻}_{名}.md   人物行動
  terms/**/<語>/<語>.md                             語（入れ子にできる）
  stories/<作品名>/meta.md                          作品（企画。上段を持つ）
  stories/<作品名>/episodes/{nnn}.md                話（**原稿そのもの。上段を持たない**）
```

**`terms/` だけは世界線でディレクトリを切らない。** どの世界線の語かは
上段の `世界` が持つ（下位の語は上位から引き継ぐ）。
**`characters/` は世界線ではなく出身地で切る。** どの世界線かは、その出身地が
どの世界線の下にある場所かで決まる。

決まりは四つ。

- **ディレクトリ名と同じ名前の md だけが、そのレコード。** 場所・個体・人物・語、
  どの種類でも同じ規約。だから `history.md` や `解釈表.md` を隣に置いてよい。
  それは自由文書として読み飛ばされる
- **`{時刻}` は `{年}_{mm}_{dd}`。** 時刻まで要るときだけ後ろに `{hhmmss}` を足す
  （`4340_01_01_耐用年数の満了.md` / `4340_01_01_093000_耐用年数の満了.md`）。
  **月日は二桁で揃える。年は西暦で、上限はない**（`99999_01_01_…` も置ける）
- **上段の中は `y/mm/dd hh:mm:ss` で書く。**
  後ろから欠けた分は書かなくてよい（`4360/7/12` / `4360`）。
  **ファイル名も上段も、この二つの書き方だけ**（`tools/stamp.py`）
- **id は書かない。** 読み込むときに、上位のレコードの id と自分の名から採番する
  （`ノウル/森`、`SFファンタジー/ノウル/森/4340_01_01_耐用年数の満了`）。
  **他を指す欄（`親` `場所` `出来事` `分類` `種族` `所属`）には名前を書く。**
  同じ名が二つあると寄せ先が決まらないので、そのときは名のほうを分ける
- **入れ子が所属を表す。** `ムシュヴァン/商人組合/` と置けば、
  商人組合がムシュヴァンの内側にいることが構造で分かる

### 種別・個体・人物

| | 何を入れるか | 例 |
| --- | --- | --- |
| **種別**（`objects/<世界線>/<種別>.md`） | **型。** 何であるかの分類 | 国、組織、仕組み、魔族 |
| **個体**（`objects/**/<個体>/<個体>.md`） | **その型の、名前のある群** | ムシュヴァン、神殿、森、さいはい |
| **人物**（`characters/<出身地>/<人名>/<人名>.md`） | **一人ひとりの人間** | ロウタ、イエスカ、マータス |

**種別のファイルにも `種別` の欄がある。** 型そのものを大きく束ねる札で、
いま使っているのは `系統`（魔族・オクノなど、生まれで決まるもの）・
`集まり`（国・組織、人が寄って作るもの）・`機構`（仕組み、動きつづけるもの）の三つ。
**個体の側は `分類` に種別の名を書く**（`分類: 国`）。

**種別 1 に対して個体が何個でもぶら下がる。**
個体と人物だけが、居場所と行動の時系列を持つ。行動の主語になれるのはこの二つである。

#### 個体と人物の線引き

**「みんな」と言えるなら個体、「この人」としか言えないなら人物。**

- **個体は群の振る舞いを持つ。** 魔族が追われる、商人組合が名簿を握る、
  神殿が登録を絞る。誰か一人の意思ではなく、**まとまりとしての動き**
- **人物は一人ひとりの中身を持つ。** 何を欲しがり、何を信じ違え、何を恐れるか。
  背丈も、一人称も、口調も、人物にしかない

**人物は種族として個体を指す。** `種族` に種別、`所属` に個体を書けば、
「商人組合に属する魔族の娘」が一行で立つ。
**群の設定を人物の側へ写さない。** 魔族の性質は種別に一度だけ書く。

#### 人物がいちばん細かい理由

本文は一人称・二人称・三人称で人を指す。**その三つが決まっていないと書けない。**

| 欄 | 何のためにあるか |
| --- | --- |
| `一人称` `二人称` | 台詞が誰のものか、読者が名札なしで分かるため（characters.md） |
| `三人称` | **地の文がこの人物をどう呼ぶか。** 途中で変えない |
| `口調` | 語彙・文の長さ・語尾。**語尾芸に頼らない** |
| `性格` `感情` `思想` | 同じ状況で何に注目し、何に揺れ、何を正しいと思うか |
| `欲` `嘘` `必要` | 造形の芯。**設定表に体重を書くより、この 3 行が効く** |
| `恐れ` | 引き返す線。ここを踏ませると場面になる |
| `能力` `代償` | **代償の無い能力は書かない。** 制限のない設定は物語を殺す |
| `性別` `背丈` `体格` `見た目` | 絵にするとき迷わない分だけ |

**空欄でよい。** 決まっていないことを埋めるために作らない。
決めたなら、**本文より先にここへ書く**（workflow.md）。

### 語と個体は役割が違う

「さいはい」という**組織**は個体、「さいはい」という**語**（正式名称は再配分機構）は語。
**名前は語の側、振る舞いは個体の側。** 両方あってよい。

## 出来事は一種類しかない

**起きたこと・数・間柄・張っているもの。全部「出来事」として積む。**
違いは `種別` だけ。

| 種別 | 何を入れるか | 書き方 |
| --- | --- | --- |
| （自由） | 起きたこと | 終わっていないなら `終` を空にする |
| `指標` | 数で追えるもの。人口・資源・値段 | 名を「人口 27400000 人」の形にする |
| `関係` | 誰と誰が、どういう間柄か | 下を見る |

自由の側で実際に使っている札は、`災害` `制度` `政治` `技術` `経済` `争点` `移動`
`発見` `時代`。**増やす前に、この九つのどれかで済まないか見る。**

`関係` は、本文の書き出しの形まで決まっている。

```markdown
# 命令を送る側と、拒めない側          ← 種別: 関係

**強度 -2**（-3 敵対 〜 3 親和。0 は無関心）。

間柄: さいはい ↔ 采配
```

**関係は両者から `actions/` で吊る。** 片側からしか吊らないと、
片方の断面にしか出ない。

### `/` で付ける注記

`種別` の後ろに `/` で注記を足せる。**断面の出しかたが変わる。**

| 注記 | 意味 | 断面での扱い |
| --- | --- | --- |
| `/裏` | 住人が知らない。**作者だけ** | 既定では伏せる。`--full` で出る |
| `/死語` | 使われなくなった語 | 既定では出さない |
| `/候補` | まだどの作品も採っていない呼び名 | 既定では出さない |
| `/設定側` | 本文に出さない語 | 既定では出さない |

`/裏` は、解釈表.md
「表の物語の本文には、裏の語を一つも出さない」を、**記録の側から守るため**にある。

## 無限に続けるための考え方

### 世界は割り算でできている

`SFファンタジー` の骨格は一本の式である——**暮らし向き ＝ 取れる分 ÷ 人の数**。

この式に触るものは、全部物語になる。分子が減れば事件になり、分母が減れば儀式になり、
**誰が分ける権利を持つか**でそのまま政治になる。地球ではそれが政策になり、
ノウルでは生贄になった。**同じ割り算が、星ごとに違う顔をしているだけ**である。

だから `指標` の出来事は飾りではない。**分子と分母を置く場所**であり、
そこが動いた瞬間、書くべき場面が生まれる。

### イベントは作者の意思で起こす

事件を値の推移から機械的に導かない。**何を起こすかは、作者が決める。**
物語が停滞する話数があってもよい。動きがないことも、そのまま書いてよい。

`指標` と `関係` は、次に何を起こすかを考えるための手がかりであって、
それ自体が話を要求する仕組みではない。分子・分母・間柄がどう動いているかを
読んで、そこに作者が意思で事件を差し込む。

### 過去は消さない。積む

**追記式。** 行を書き換えず、新しい年のファイルを足す。
`指標` の値が 3540 年に 27000000、4340 年に 10000000 なら、
**八百年かけて減ってきた**ことが残る。推移そのものが、次に書くときの手がかりになる。

## 書く前——断面を取る

その話が立つ**場所と年**を決めて、断面を出す。設定ファイルを読み直すより先にこれ。

```
python3 tools/novel.py brief --place ムシュヴァン --time 4360
```

出るもの。

| 節 | 何が読めるか |
| --- | --- |
| 1 いまの数値 | 分子と分母。その時点で最後に記録された値 |
| 2 続いている出来事 | まだ終わっていないもの。**背景に置くべきもの** |
| 3 直近 60 年の出来事 | 登場人物が覚えている範囲の過去。`--reach` で変えられる |
| 4 その場にいる者 | 生没つき。死んだ者と生まれる前の者は出ない |
| 5 この射程での行動 | 誰が何をして、**何を失ったか** |
| 6 種別「火種」の出来事 | 過去に立てたものがあれば出る。**必須ではない。次に何を起こすかは作者が決める** |
| 7 ここで使える語 | その場所に届いている語だけ |
| 8 ここからは見えないこと | 件数だけ。`--full` で中身が出る |

`--place` は、**その場所・その内側・その外側**に効く。
外側から来たものには「（広域）」が付く。それが**周辺環境**である。

八節に件数が出るのは意図的で、「**この時点には、まだ書けないことが 4 件ある**」と
分かっているほうが、住人の無知を正しく書ける。

- **本文を書くとき**: `--full` を付けない。伏せられたまま書く
- **裏を設計するとき・繋ぎを確認するとき**: `--full` を付ける

## 書いたあと——記録に戻す

workflow.md「3 世界観更新モード」を見る。**文章に書き戻したら、記録にも足す。**

```
novels/worlds/SFファンタジー/ムシュヴァン/events/4361_03_01_登録の値が二倍になる.md
```

```markdown
---
種別: 経済
---

# 登録の値が二倍になる

（何が起きたか。長さに制限はない）
```

最後に検める。**error が残ったまま次の話へ行かない。**

```
python3 tools/novel.py check
```

## 数を本文に出さない

principles.md は**ステータス画面・レベル・数値で強さを説明することを禁じている。**
この記録はそれに反しない。**反しないように使う。**

- 記録の数は、naming.md でいう**設定側の名**と同じ扱い。**作者だけが見る**
- 「器 4」と本文に書かない。**書くのは、四人ぶんの井戸を一人で汲み上げてしまう場面**
- 数が動いたことは、**必ず場面として書く**

**数は、何を書くかを決めるためにある。何を書いたかを説明するためではない。**

## 形は一か所で決まっている

**`tools/schema.py`（SQLAlchemy のモデル）が、DB の列も上段の欄も決めている。**
欄を増やしたければ `schema.py` を直す。**マークダウン側に勝手な欄を足さない。**
スキーマに無い欄を書いたファイルは、**黙って捨てられずに `check` で止まる。**

| 欄 | どのレコードにあるか |
| --- | --- |
| `名` | 場所・出来事・種別・個体・人物・語。**書かない。** ディレクトリ名かファイル名が名になる |
| `種別` | 場所・出来事・種別・個体・語 |
| `読み` | 種別・個体・人物 |
| `親` | 場所（上位の場所）・出来事（上位の出来事） |
| `始` `終` | 場所・出来事・種別・個体・居場所・行動・人物居場所・人物行動 |
| `生` `没` | 人物（`始` `終` ではなくこちら） |
| `時` | 出来事（省略時はファイル名の時刻） |
| `場所` | 出来事・居場所・人物居場所・語 |
| `分類` | 個体（どの種別か） |
| `世界` | 種別・個体・語（個体は省略時に `objects/<世界線>/` のディレクトリ名） |
| `星` | **語だけ。** 種別と個体にこの欄は無い |
| `世界番号` `惑星番号` `経度` `緯度` `高度` `X` `Y` `Z` | 場所。**任意。** 天文の位置が要るときだけ |
| `出身` | 人物（省略時はディレクトリ名。どの場所で生まれたか） |
| `種族` `所属` | 人物（種族は種別、所属は個体を指す） |
| `性別` `背丈` `体格` `見た目` | 人物。`背丈` は cm の数 |
| `一人称` `二人称` `三人称` `口調` | 人物 |
| `性格` `感情` `思想` `欲` `嘘` `必要` `恐れ` | 人物 |
| `能力` `代償` | 人物。**代償を空にしない** |
| `世界影響力` | 個体・人物。**任意の数。** この個体・人物が世界の動きにどれだけ関わるかの重み。
  高いほど、その存在の一手が世界に及ぶ範囲が広い |
| `出来事` | 行動・人物行動（どの出来事に関わったか） |
| `語り` `状態` | 作品（`meta.md`）。`始` は立つ年、`場所` は立つ場所 |
| `話数` `題` `字数` | 話。**書かない。** ファイル名・見出し・原稿の長さから読む |

居場所と行動には、ここに加えて次の決まりがある。

- **居場所（`places/`）の `場所` は、書かなければファイル名の `{時刻}_{場所}` から採る。**
  ファイル名と同じなら省いてよい
- **行動（`actions/`）の `出来事` は必ず書く。** こちらは採番されない。
  **ファイル名は「その人が何をしたか」、`出来事` は「どの出来事に関わったか」**で、
  一致しなくてよい（`4360_11_03_村を出る.md` の `出来事` が `一人多いと名指される`）。
  指す先の出来事を先に `events/` へ置いてから吊る
- **`始` と `終` は書かなければファイル名の時刻が `始` に入る。**
  一日で終わる行動は `始` と `終` に同じ時刻を書く

**本文（`episodes/{nnn}.md`）には上段を書かない。** 話のレコードは原稿を
`text` に持つだけで、話数はファイル名（三桁ゼロ埋め）、題は先頭の見出し、
字数は原稿の長さから読む。`dump` も原稿だけを書き戻す。
**作品の `meta.md` のほうは上段を持つ**（`世界` `場所` `語り` `状態` `始`）。
断面を取るのに要る二つ（立つ場所と立つ年）が、ここから引ける。

```
python3 tools/novel.py sql "SELECT number, title, letters FROM episode"
```

雛形はツールが出す。

```
python3 tools/novel.py template --kind 場所      # 場所/出来事/種別/個体/居場所/行動/人物/人物居場所/人物行動/語/作品/話
```

## 作業中の参照はDB、記録はマークダウン

**マークダウンが正。DBは組み直せる派生物**（`novels/novel.db` は git に入れない）。
それを踏まえて、作業の運び方は次のとおりにする。

- 作業を始めるときに `build` して DB を今の記録に合わせる。作業中の検索・関係の
  確認は `sql` `show` `brief` など DB 経由の読み取りで済ませ、
  マークダウンを何度も読み直さない
- **変更は必ずマークダウンのファイルに書く。** DB の行を直接書き換えて
  済ませない。作業の終わりに `check` → `build` を通し、記録と DB を合わせ直す
- 上段の欄に相当する情報（`種別` `所属` `見た目` など）は、
  本文（`text` カラムに入る側）に紛れ込ませず、**必ず欄の側に書く**。
  本文は、欄に書けないこと・場面の記述だけを持つ

| `tools/tables.json` | `roll.py` が引くテーブル |

| | |
| --- | --- |
| `check` | 不備を探す。**error があれば終了コード 1** |
| `build` | 記録から `novels/novel.db` を組み上げる |
| `brief --place <場所> --time <年>` | 断面を出す。`--reach <年数>` で 3 節の射程（既定 60 年） |
| `list --kind 語 --world <世界線>` | 一覧 |
| `show <名>` | 一件読む |
| `episodes --story <作品名>` | 直前の話を読む（既定 10 話）。`--before <話数>` `--count <数>` `--list` |
| `template --kind 人物` | 雛形を出す |

`--kind` に入るのは日本語の呼び名のほう
（`場所` `出来事` `種別` `個体` `居場所` `行動` `人物` `人物居場所` `人物行動` `語`
`作品` `話`）。
| `index --world <世界線>` | 用語索引を `novels/worlds/<世界線>/glossary.md` に書き出す |
| `sql "SELECT …"` | 直接問い合わせる |
| `dump` | db の行をマークダウンへ書き戻す。**内容が変わらないファイルは書き直さない** |

`sql` は、断面では出ない問いに使う。

`dump` は、db を直接いじった（または `sql` で更新した）ときに使う。
置き場所はまず今のマークダウンから探し、見つからない新しい行だけ
`novels/<worlds|objects|characters|terms>/` に id から素直な場所を組んで置く。
**それでも、変更は作業の終わりに必ずマークダウンへ書き戻す**（前節）。

```
python3 tools/novel.py sql \
  "SELECT name, time FROM event WHERE kind LIKE '火種%' ORDER BY time"
```

`novels/novel.db` は git に入れない。**記録から何度でも組み直せる**ので、
差分が読めないバイナリを履歴に残す意味がない。
