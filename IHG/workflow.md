# 執筆ワークフロー

作業は**三つのモード**に分かれている。**一度に一つだけやる。**
混ぜると、設定を作りながら本文を書き、本文を書きながら設定を直すことになって、
どちらも中途半端に終わる。

```
  ┌──────────────┐   ┌──────────────┐   ┌──────────────┐
  │ 1 世界観構成  │ → │ 2 ストーリー  │ → │ 3 世界観更新  │
  │   モード      │   │   生成モード  │   │   モード      │
  └──────────────┘   └──────────────┘   └──────────────┘
         ↑                                      │
         └──────────────────────────────────────┘
   場所・個体・人物         話(story /          起きたことを
   ・語・筋書きを作る        episode)を書く      世界の側へ戻す
```

1 は最初の一度だけ。**あとは 2 と 3 をひたすら回す。**

|                      | 読むもの                              | 書くもの                             |
| -------------------- | ------------------------------------- | ------------------------------------ |
| **1 世界観構成**     | `IHG/` と、あれば既にある世界         | 場所・個体・人物・語・筋書きのレコード |
| **2 ストーリー生成** | **直前の 10 話**と断面(`ReadBrief`)   | 話(`story` / `episode`)のレコードだけ |
| **3 世界観更新**     | 書いた本文                            | 場所・個体・人物・語のレコード       |

**2 のあいだは世界の側を触らない。3 のあいだは本文を触らない。**
本文を書いている途中で設定を作りたくなったら、メモに書き出して 3 まで持ち越す。

記録の持ち方は chronicle.md。形は `DEM/db/schema.py` が決めている。

## どのモードでも共通：db は DEM/claude_interface 越しにしか触らない

**`novel.db` を直に開かない。`worlds/` の md も直に開かない**(md は db の写し。
書き出しは `DEM.claude_interface.sync.export_db.ExportDb().run()`)。読むのも
書くのも `DEM/claude_interface/` の入口を import して呼ぶ。
**今ある入口の一覧は CLAUDE.md の表。無い操作を推測で呼び出そうとしない。**

**「作る」と「確定する」は別の入口。** `CreateRandom*` は辞書を返すだけで
db に触れない。`Commit*` を呼んで初めて db に残る。

**一度に出せるものは一度に出す。** 入口は呼ぶたびに db を開き直す。モード 2 の
材料(同期の確認・直前の話・断面・顔ぶれ)は `StartStory` 一本で出るので、
個別の入口は出す範囲を変えたいときだけ使う。

**SQL は組み立てない。** 引く条件は時刻とレコードの id で表し、足りない
引き方は `DEM/data_access_logic/query/` に関数を足して、
`DEM/claude_interface/` に一つ入口を被せる。

# 1 世界観構成モード

**場所・個体・人物・語・筋書きを作るところまで。**
このモードでは話(`story` / `episode`)を一行も書かない。

## 1-1 企画を先に決める

細かい設定より先に、これだけ決める。設定から始めると、
**面白くない設定資料ができあがる。**

- **ログライン**: 「誰が、何を望み、何に阻まれる話か」を 1 文で
- **売り**: 読者が友達に説明するときの一言
- **読後感**: 読み終わったときにどんな気持ちでいてほしいか

**どれも AI が先に決めない。** まず作者に聞く。作者が「アイデアがない」と
言ったときだけ、AI が案を出す(principles.md「発想の主権」)。

## 1-2 世界を起こす

**物語に必要な分だけ作る。** 世界地図を全部埋める必要はない。
作るべきは「**主人公の行動を制限するルール**」と「**対立の種**」。
制限のない世界では何も起きない。イベントを起こすのは作者の意思であって、
値の推移が自動で話を要求する仕組みではない。

作る順番はこれで固定する。**前を飛ばして後ろを作らない。**

| 順  | 何を                             | どう作るか                                          |
| --- | -------------------------------- | --------------------------------------------------- |
| 1   | **世界線**(いちばん外の場所)     | `CreateRandomPlace` → 名を決めて `CommitPlace`      |
| 2   | **星・大陸・地形**(場所の木)     | 同上。`parent_id` で親に吊る                        |
| 3   | **個体**(国・組織・群)           | `CreateRandomObject` → 名を決めて `CommitObject`    |
| 4   | **人物**(一人ひとりの人間)       | `CreateRandomCharacter` → 名を決めて `CommitCharacter` |
| 5   | **出来事**(年表・指標・関係)     | `CreateRandomEvent` → `CommitEvent`                 |
| 6   | **語**                           | **確定する入口がまだ無い**(下の注)                  |
| 7   | **筋書き**(出来事生成の方向づけ) | `CommitPlot`                                        |

> **注:** `term`(語)を db へ確定する入口は `DEM/claude_interface/` にまだ無い。
> 必要になったら、CLAUDE.md「入口の作り方」に沿って足す。
> **無いものを推測で呼び出さない。** 既にある語を見るのは `SearchTerms`。

**個体は「群としてどう動くか」を書く。** `kind` の欄は無いので、国・組織・商会の
どれなのかは `text` に書く。何を決められて、誰に対して力を持つのかまで書いて
おくと、出来事の生成でその個体が行為の主体として立つ(chronicle.md)。

**人物は作品が決まってから。** 世界だけ作るあいだ、人物は要らない。
群としての振る舞い(個体)と、一人ひとりの中身(人物)を混ぜない(chronicle.md)。

**人物の下書きを作る前に、`ListPlots` で今の筋書きを読む。** その人物が立つ
場所に掛かるもの・場所を問わないものを踏まえて `text`・性格の方向づけを決める。
`CreateRandomCharacter` が返す `name` は `仮名0` のような仮の値なので、
`IHG/naming.md`「人名」の手順で名を決めてから `CommitCharacter` に渡す。

**既存の世界を使い回すなら、このモードは要らない。** 2 から始める。
一つの世界で何本も書けるのがこの構成の狙いである。

## 1-3 アバウトなところの決め方

人口・年代・比率のように、設定から読めない数や要素も、順番は 1-1 と同じ。

1. まず作者に聞く
2. 既にある語・個体(`SearchTerms` `ListObjects`)に当てはまるものがあれば提示する
3. 作者にアイデアがないときだけ乱数で振る。**AI の第一想起で埋めない**
   (principles.md)

**`DEM/randomizer/roll.py` は現状動かない**(引く先の `tables.json` が無い)。
直すか作者に確認するまでは `random` で代用し、**引いた目とシードを会話に残す。**

## 1-4 締め

**作っただけで終わらせない。** `Commit*`(確定する側)まで呼んだかを確かめる。
一覧(`ListPlaces` `ListCharacters` `ListEvents` `ListPlots`)で、
入ったはずのものが入っているか見る。

# 2 ストーリー生成モード

**世界の側を元に、話(`story` / `episode`)を書く。**
このモードでは世界の側を一行も書き換えない。

順番は **同期の確認(2-0)→ 直前の 10 話(2-1)→ 展開(2-2)→
顔ぶれと断面(2-3)→ 本文(2-4)→ 推敲(2-5)**。
**展開を考えるのは、前の話を読んだあと。**

## 2-0 未同期の話が残っていないか見る

話には `synced`(同期フラグ)がある。**その話で起きたことが世界の側へ戻って
いるか**を持つ欄で、モード 3 を通すまでは下りている。下りている話があるあいだ、
`StartStory` は材料を出さずに止まる。古い記録の上で次の話を組み立てると、
断面も顔ぶれも一話ぶん古いままになるからである。

```python
ListUnsyncedEpisodes(<作品id>).run()        # 未同期の話を並べる
SetEpisodeSynced(<作品id>, <話数>).run()    # モード 3 のあと、立てる
```

**止まったら、モード 2 をいったん置いてモード 3 をやる。**

**2-0 から 2-3 までを一度に出す入口がある。**

```python
StartStory(<作品id>, time=None).run()   # time を省くと作品の立つ年
```

同期の確認・作品の見出し・直前の話・断面・顔ぶれが、この一本で出る。
未同期の話があれば、そこで止まる。下の節は、その中身を一つずつ見たいときと、
出す範囲を変えたいときに使う。

## 2-1 直前の 10 話を読む

**展開を考える前に、直前の 10 話を読む。** ここを飛ばさない。
前の話で誰が何を言ったか、どこで終わったかを覚えていないまま次を考えると、
同じ場面をもう一度書く・前話の引きを拾い落とす・口調が変わる。

```python
ReadEpisodes(<作品id>, count=10, before=None).run()
```

読むのは原稿そのもの(`episode.text` がそのまま出る)。
10 話に満たなければ、あるだけ出る。
**読んでから 2-2 に進む。**

## 2-2 展開を決める

**結末を先に決めない。** 次に何が起きるかは、そのつど候補を出して相談する。

- 候補は次から拾う: **直前の 10 話でまだ回収していない引き**(2-1)、
  登場人物の直近の情動(欲・恐れ・嘘・必要。characters.md)、
  まだ終わっていない出来事、その場所にいる別の人物・個体、
  **主人公の周辺**(2-3、`ReadSurroundings`)に出た居合わせる者・出来事の来歴
- 候補が浮かばないときは複数出して作者に提示する。
  **作者が選ぶ。AI が決めない**(principles.md「発想の主権」)
- 山場・引きは 1 話ずつ、書く直前に決めてよい

**作品ごとの筋書きを置く場所は db に無い。** `plot` レコードは**場所**に掛かる
筋書きで、常駐ループの出来事生成を方向づけるためのもの(`CommitPlot`)。
話の展開そのものは、決まった分だけ会話に残して次の話で使う。

作品がどの世界線のどこ・いつに立つかは `story` レコードが持っている
(`ListStories` で見る)。断面を取るのに要る二つ(立つ場所と立つ年)はここから引く。

## 2-3 顔ぶれと断面を取る

**設定を頭から読み直さない。** 材料は二枚で足りる。

### 顔ぶれ(誰がいて、その人に何が起きたか)

```python
ReadCast(<作品id>, time=None).run()
```

作品が立つ場所の**一つ上**を基準に、その配下の場所にその時点で居る
人物と個体を集め、一人(一群)ずつ直近の出来事を並べる。

一つ上を基準にするのは、その話に出せる者が村の中だけとは限らないからである。
隣の集落にいる者も、島を回っている群も、同じ枠に入ってくる。
**その話に誰を出せるかは、ここで決める。** 思いついた名前を先に置かない。

### 断面(世界がどうなっているか)

```python
ReadBrief(<場所id>, "4360", reach=60).run()
```

**顔ぶれも断面も年で見る。** `"4354"` はその年いっぱいを指すので、
同じ年の後半に書き足した出来事も材料に入る。

まだ終わっていない出来事は何か、誰がその場にいて、何が張っているかが出る。
**直近の出来事は既定で 60 年ぶん。** もっと遡りたいときは `reach=200` と伸ばす。

> **`full=True` を付けない。** 付けると住人が知らないこと(`hidden` の
> 立った出来事)まで出て、それを本文に書いてしまう。裏を設計するときだけ付ける。

### 喋る人物を一件ずつ読む

```python
ReadCharacter(<人物id>, time=None).run()
```

一人称・二人称・三人称・口調がここにある。**本文の呼び方はこれに従う。**
書きながら決め直さない。決め直したくなったら、それはモード 3 の仕事である。

### 主人公の周辺(ReadSurroundings)

**主人公については、必ずこれも通す。**

```python
ReadSurroundings(<主人公の人物id>, "4354", reach=60).run()
```

`ReadCast` が作品の立つ場所を軸にするのに対し、こちらは**主人公自身の
居場所**を軸にする。その時点で主人公と居合わせる人物・個体と、
直近 `reach` 年ぶんの出来事が、主人公から見た射程で出る。
顔ぶれ・断面が話全体の見取り図だとすれば、こちらは主人公一人分の
展開の種になる。2-2 の材料に含める。

## 2-4 本文

```python
CommitEpisode({"story_id": …, "number": …, "title": …, "text": …}).run()
```

**1 話 1 レコード**、字数は入口が数えて入れる。
同期フラグは必ず下りた状態で入る(立てるのはモード 3 の締め)。

書きはじめる前に、その話の中で**変化するもの**を 1 つ確認する。
関係・情報・状況のいずれかが動かない話は、**削れる話**である。

- 書く順番は場面の頭から順に。難しい場面を飛ばして後から埋めない
  (前後のテンションが合わなくなる)
- **要約で済ませない。** 「〜という展開があった」で流さず、場面として書く
  (**場面で書くのは本文だけ。** 出来事の `text` は記録として書く。chronicle.md)
- **数を本文に出さない。** 記録の数は作者だけが見る(chronicle.md)
- 途中で新しい設定が生まれたら、**本文にだけ書いて、メモに控える**。
  世界の側へ戻すのは 3 の仕事

## 2-5 推敲

checklist.md を上から順に当てる。
直しながら読むのではなく、**通読 → メモ → 直す**の順で。

# 3 世界観更新モード

**書いた本文から、世界の側を更新する。**
本文を書くと必ず新しい設定が生まれる。街の名前、酒場の主人、力の副作用。
**後回しにすると必ず矛盾する。**

## 3-1 本文の側を先に直す

**本文が正で、記録が従。** 順番を逆にしない。

- 新しく出した場所 → `CreateRandomPlace` → `CommitPlace`(既にある場所の
  書き直しは `UpdatePlace`)
- 新しく出した人物 → `CreateRandomCharacter` → `CommitCharacter`。
  **台詞を一つでも喋らせたら登録する。** 一人称・二人称・三人称を必ず埋める。
  能力・特徴は `text` に文章で書く(`UpdateCharacter`)
- 新しく出した個体(群) → `CreateRandomObject` → 名を決めて `CommitObject`。
  **組織の名前を本文に出した時点で登録する**
- 新しく出した語 → **確定する入口がまだ無い。** 必要になったら
  CLAUDE.md「入口の作り方」に沿って足すか、その場で作者に相談する

既存の設定と食い違う本文を書いてしまったら、本文のほうを直す。
既存の設定は基本的に変更しない。

## 3-2 起きたことを出来事として積む

一話書いたら、最低でもこれだけは足す。**上書きしない。新しい時刻を足す。**

| 何を                       | どこに                                                                   |
| -------------------------- | ------------------------------------------------------------------------ |
| その話で起きたこと         | `CommitEvent`(`location_id` と、関わった `character_ids` `object_ids`)   |
| 動いた数                   | 同上。`name` を「人口 27400000 人」の形に                                |
| 変わった間柄               | 同上。`name` を間柄の一言にし、双方を `character_ids` / `object_ids` に  |
| 主要人物がやったこと       | 同上。**行動も出来事の一件。** 掛かり先があれば `parent_event_id` を書く |
| 情動が動いたこと           | `CommitEvent` の `character_drives` に乗せる(出来事に紐づかないときだけ `CommitCharacterDrive`) |
| 能力・特徴が変わったこと   | `UpdateCharacter` で `text` を書き直す                                   |

出来事の `text` は**記録として書く**(chronicle.md「出来事の text は記録として
書く」)。小説として書くのは本文の側だけ。

## 3-3 締め

```python
SetEpisodeSynced(<作品id>, <話数>).run()   # 同期フラグを立てる
ExportDb().run()                            # 読む用の md(worlds/)を作り直す
```

**記録へ戻さないまま次の話へ行かない。** 次の断面が嘘になる。
**同期フラグを立てないまま次の話へも行かない。** 2-0 で止まる。

## どのモードにいるか分からなくなったら

| 頼まれたこと                                     | モード                            |
| ------------------------------------------------ | --------------------------------- |
| 「新しい世界を作って」「この星に国を足して」     | 1                                 |
| 「3 話を書いて」「続きを書いて」                 | 2                                 |
| 「書いたぶんを設定に反映して」「記録を更新して」 | 3                                 |
| 「設定の矛盾を直して」                           | 1(既存の世界を直すのも構成のうち) |

**頼まれていない話数を勝手に書き足さない。**
**指示がないかぎり、過去の原稿を「ついでに」推敲して書き換えない。**
